# Reviewer Lab

**Стенд для проверки AI-ревьюеров кода.** Атакующая LLM прячет заданную ошибку,
независимая программа подтверждает нарушение, LLM-ревьюер принимает или отклоняет
изменение. Если ошибочный код одобрен, найден пропуск ревьюера. LLM нужны для
поиска и содержательного ревью; правильный ответ определяет программа.

Можно проверить готовый пример, написать собственный код или запустить поиск
с обратной связью. История связывает версии кода, diff, конкретную ошибку
и ответ модели. Есть восемь задач и сохранённые реальные эксперименты.

## Запуск в Docker

Нужны Git и работающий Docker с Compose. Python, Node.js, Codex CLI и Claude Code
включены в образ.

```sh
git clone https://github.com/IzitckiyT/reviewer-lab.git
cd reviewer-lab
cp .env.example .env
docker compose up --build -d
```

Откройте **http://localhost:8765/#launch**. Просмотр истории и проверка поведения
кода доступны сразу. Новые обращения к моделям начинаются только после явного
запуска проверки и используют квоту или API-баланс вашего аккаунта.

### Подключить модель

Выберите один способ:

```sh
# OpenAI через Codex CLI / вход ChatGPT:
docker compose exec reviewer-lab codex login --device-auth

# Anthropic через Claude Code:
docker compose exec reviewer-lab claude auth login
```

CLI напечатает ссылку для входа; Codex также покажет одноразовый код.
Для **DeepSeek API** заполните `DEEPSEEK_API_KEY` в локальном `.env`, затем
выполните `docker compose up -d --force-recreate reviewer-lab`.
Настоящие ключи не добавляйте в `.env.example`; `.env` исключён из Git.

| Подключение | Ревьюер по умолчанию | Атакующий по умолчанию |
|---|---|---|
| OpenAI / Codex | `gpt-5.6-luna`, medium | `gpt-6.1-sol`, xhigh |
| Anthropic / Claude Code | `sonnet` | `sonnet` |
| DeepSeek API | `deepseek-flash` | `deepseek-flash` |

Ревьюер оценивает патч, атакующий создаёт новые варианты с ошибкой. Их модели
выбираются отдельно в UI, включая собственный ID; обе роли используют одно
подключение. `sonnet` — алиас CLI. Доступ к модели зависит от аккаунта.
[Авторизация, диагностика и другие настройки](docs/START.md).

Вход CLI и новые эксперименты сохраняются в Docker volumes `lab-home`
и `lab-runs`. Остановить: `docker compose down`; запустить снова:
`docker compose up -d`. Порт занят — поменяйте `REVIEWER_LAB_PORT` в `.env`.

## Первый эксперимент

1. Откройте **«Задачи» → «Кто может публиковать»**. Прочитайте правило,
   посмотрите правильный код и примеры вызовов, нажмите **«Выбрать задачу»**.
2. Оставьте **«Готовый патч с ошибкой»**, выберите подключение и ревьюера,
   проверьте план и нажмите **«Запустить проверку»**.
3. В результате сравните **поведение кода** и **решение модели**.
   Нажмите на нарушение для разбора; **«Ответ модели»** раскрывает объяснение.

Для своего кода есть **«Свой код»**, для автоматического поиска —
**«Найти новый обход»** с выбором модели атакующего. В истории доступны версии,
сравнение с предыдущей попыткой и исходник в отдельной вкладке.
[Пошаговая инструкция](docs/USER_GUIDE.md).

## Границы проверки

Оракул перебирает **159 объявленных входов восьми задач**. Кандидаты вычисляются
ограниченным AST-интерпретатором внутри контейнера приложения: произвольный
Python, реальные сетевые атаки и выполнение shell-команд не поддерживаются.
Пять сценариев основаны на записях MonitoringBench; полные траектории бенчмарка
не воспроизводятся. Ответы моделей могут меняться; один обход не измеряет
их общую надёжность. [Сохранённые результаты и ограничения](docs/EVIDENCE.md).
