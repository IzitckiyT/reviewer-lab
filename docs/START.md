# Запуск Reviewer Lab

## Быстро посмотреть и понять

На macOS дважды нажмите **Start Reviewer Lab.command** в папке проекта.
Или выполните одну команду из корня проекта (Python 3.10+):

```sh
python3 run.py
```

Откроется браузер с разбором примера. По умолчанию адрес —
`http://127.0.0.1:8765/#demo`; если порт занят, программа сама выберет свободный
и напечатает фактический адрес. Для этого режима не нужны аккаунт и ключи моделей.
 Кнопка «Разобрать пример» проводит через правило, ошибочный патч, контрпример и сохранённый ответ модели. Затем в «Проверить свой патч» можно менять код и нажимать «Проверить локально».

Демо не вызывает модели. Локальный тест показывает поведение кода; его временный результат не становится новым экспериментом. Код черновика сохраняется в браузере. Для остановки сервера нажмите Ctrl+C в терминале.

## Docker

Требуется установленный Docker с Compose. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build
```

Адрес: `http://localhost:8765/#demo`. Остановка:

```sh
docker compose down
```

Если порт занят:

```sh
REVIEWER_LAB_PORT=8766 docker compose up --build
```

Docker запускает только демо: сохранённые ответы и локальные тесты. В контейнер не передаются учётные данные, Codex CLI не установлен. Файловая система контейнера доступна только для чтения, процесс работает без root. Compose публикует порт только на текущем компьютере.

Конфигурация контейнера подготовлена, но Docker-сборка в среде подготовки не выполнялась: Docker отсутствует. Проверки build и HTTP smoke включены в GitHub Actions; до их выполнения нельзя считать контейнер проверенным.

## Новый живой ответ модели

Это отдельный режим, который расходует квоту авторизованного Codex-аккаунта. Нужны актуальный Codex CLI, вход ChatGPT и доступ к моделям из `lab/transport.py`. Установка CLI сама по себе не гарантирует доступ к этим идентификаторам.

Из папки проекта выполните:

```sh
python3 run.py start --live
```

Команда проверит CLI, вход и каталог моделей **до открытия интерфейса**.
Если настройка не прошла, объяснит причину и предложит демо. Это проверка
конфигурации, а не inference: доступ аккаунта окончательно проверяется новым
вызовом модели. Откроется ручная проверка. Можно оставить демо открытым —
при занятом стандартном порте live-сервер выберет свободный.
Явный `--port` и экспортированный `REVIEWER_LAB_PORT` не подменяются.
Для отдельной диагностики: `python3 run.py doctor`.

`doctor` проверяет CLI, вид авторизации и каталог, но не делает inference. При необходимости выполните вход тем бинарником Codex, путь к которому показывает `doctor`. Его можно явно выбрать через `REVIEWER_LAB_CODEX`. В коде предусмотрен путь к CLI приложения на Mac и fallback на `codex` из PATH.

В интерфейсе выберите «Проверить свой патч», вставьте полную функцию и нажмите «Проверить патч». До трёх вызовов ревьюера при первом целевом дефекте в серии (два контроля и сам патч), затем до одного на следующую попытку. Невалидный код, исправленный дефект и другое нарушение не отправляются модели. Автоматический поиск дополнительно вызывает атакующего.

Сервер живого режима слушает только loopback. Для публичного сервиса с live-вызовами нужна отдельная авторизация и ограничение расходов, это задача следующего этапа.

## Проверить без модели

```sh
python3 run.py check
python3 -m unittest discover -s tests -v
node --test tests/test_ui_frontend.cjs
python3 run.py replay owner examples/successful-owner-bypass.py
python3 run.py verify runs/replication-collision-medium-2026-10-19
```

Node нужен только для frontend-тестов. Replay повторно вычисляет поведение сохранённого кода, verify сверяет артефакты и изоляцию контекста. Эти команды не получают новых ответов LLM.

Python напрямую не читает `.env`; это файл для Compose. Все параметры перечислены
в `.env.example`. У простого `start` режим задаётся только флагом `--live`,
сервер всегда локальный. Параметры bind/demo/public-origin через переменные
окружения относятся к расширенной команде `ui`. Она сохранена для совместимости:
`ui --demo --open` — демо, `ui --open` — live без предварительной проверки.
Для первого запуска используйте `python3 run.py`.

## Ошибки запуска

- Порт занят: обычный `python3 run.py` выберет свободный; для заданного порта
  используйте `python3 run.py start --port 8766`, для выбора ОС — `--port 0`.
- Вставлен diff: редактор принимает полный код функции `decision`, без Markdown-ограждений.
- Недоступна модель: смотрите `doctor` и точное имя в `lab/transport.py`; автоматической замены нет.
- В демо нет нового ответа reviewer: это ожидаемо. Доступны локальный тест и сохранённые ответы.
- Успешный запуск GitHub Actions пока не подтверждён. После публикации кода проверить [вкладку Actions](https://github.com/IzitckiyT/reviewer-lab/actions).

## Передать результат другому человеку

В сохранённом результате нажмите **«Скачать результат»**. Архив содержит
код, правило, точный контрпример, сохранённое решение модели и интерпретатор
из снимка эксперимента. Распакуйте и выполните `python3 replay.py`:
должно быть `matches_saved_oracle: true`. Аккаунт, сеть и установка пакетов
не нужны. Это воспроизводит локальную проверку, а не новый ответ модели.
Для временного результата демо экспорт не предлагается.
