## Docker: запустить приложение и новые эксперименты

Требуются Docker и Compose. Из папки проекта:

```sh
cp .env.example .env
docker compose up --build -d
```

Откройте **http://localhost:8765/#launch**. В образ включены Python, Node.js,
Codex CLI и Claude Code. Сервер допускает новые эксперименты; само открытие
приложения не вызывает модель. История и локальная проверка доступны без входа.

Для новых ответов подключите одного провайдера:

```sh
# Codex: ссылка и одноразовый код появятся в терминале.
docker compose exec reviewer-lab codex login --device-auth

# Или Claude Code: следуйте ссылке, напечатанной CLI.
docker compose exec reviewer-lab claude auth login
```

Для DeepSeek заполните `DEEPSEEK_API_KEY` в локальном `.env` и выполните
`docker compose up -d --force-recreate reviewer-lab`. Реальный ключ не нужно
добавлять в `.env.example`. Дополнительные варианты авторизации Claude
перечислены в шаблоне окружения. Затем выберите провайдера в UI и нажмите
**«Проверить вход»** (для настроенного API — **«Обновить статус»**);
диагностика сама по себе ответа модели не запрашивает.

Проверить подключение из контейнера:

```sh
docker compose exec reviewer-lab python run.py doctor --provider codex
```

Вместо `codex` можно указать `claude` или `deepseek`. Модели выбираются в UI,
как и при нативном запуске. Доступ и квота зависят от аккаунта провайдера.
Подробности авторизации: [Codex](https://developers.openai.com/codex/auth/),
[Claude Code](https://code.claude.com/docs/en/authentication),
[DeepSeek API](https://api-docs.deepseek.com/).

Новые серии сохраняются в volume `lab-runs` (`/app/runs`), вход CLI — в
`lab-home` (`/home/lab`). Обычный `docker compose down` сохраняет оба volume.
Контейнер работает без root, слушает только текущий компьютер; каталоги
компьютера и Docker socket в него не подключаются. Кандидаты вычисляются тем
же ограниченным AST-интерпретатором, а не произвольным Python в отдельном Docker.

- Остановить: `docker compose down`.
- Продолжить пользоваться: `docker compose up -d`.
- После обновления кода: `docker compose up --build -d`.
- Логи: `docker compose logs -f reviewer-lab`.
- Порт занят: задайте `REVIEWER_LAB_PORT=8766` в `.env` и повторите запуск;
  адрес станет `http://localhost:8766`.

Отдельное демо с отключёнными моделями:

```sh
docker compose stop reviewer-lab
docker compose --profile demo up --build -d demo
```

Откройте `http://localhost:8765/#demo`, либо ваш порт из `.env`.
Для возврата к новым экспериментам: `docker compose stop demo`, затем
`docker compose up -d reviewer-lab`. У демо нет доступа к volume авторизации.
Оба сервиса используют один порт, поэтому одновременно их запускать не нужно.

## Нативный запуск эксперимента

Нужен Python 3.10+. На macOS дважды нажмите **Start Experiment.command**.
Или выполните из папки проекта:

```sh
python3 run.py start --live
```

Откроется экран **«Новая проверка»**. Первый запуск:

1. Слева откройте **«Задачи»**. Вы увидите восемь коротких описаний ошибок.
2. Откройте нужную задачу. Внутри — ситуация, правило, скрытое нарушение и
   сравнение «По правилу / Код с ошибкой» на одном примере.
3. Нажмите **«Выбрать задачу»** или **«Перейти к запуску»**, если она уже выбрана.
   Откроются настройки. Просмотр и выбор задачи ничего не запускают.
4. Выберите **«Подключение модели»** — Codex CLI, Claude Code CLI или DeepSeek API —
   и **«Модель ревьюера»**. Для своего ID есть **«Другая модель…»**.
5. Прочитайте блок **«Что получите»** и число обращений, затем нажмите
   **«Запустить проверку»**.

Сменить задачу можно прямо в настройках через **«Выбрать задачу · 8»**.
Строка сначала открывает описание; выбор подтверждается отдельной кнопкой.
Для текущей задачи есть **«Подробнее о задаче»**: пример ошибки и источник
спрятаны там, чтобы не перегружать экран запуска. Закрытие описания сохраняет
настройки. По умолчанию проверяется готовый код с ошибкой: два проверочных
примера и сам выбранный код. Остальные режимы свёрнуты.

В левом меню **«Новый запуск»** открывает настройки, **«Задачи»** — каталог,
**«История»** — сохранённые запуски, **«Свой код»** — ручной редактор.
Раскройте **«Быстрый старт»**, если нужно вспомнить цель: даём AI код с известной
ошибкой, получаем решение и проверяем, заметил ли ревьюер нарушение.

После запуска откроется его страница. Она обновляется каждые 1,5 секунды:
видны текущая роль и модель, время, завершённые вызовы и известный расход.
В первой проверке главным показан выбранный код: какое правило он нарушает
и одобрила ли его модель. **«Ответ модели»** раскрывает причину решения;
**«Все ситуации»** — конкретные разрешения и запреты кода.
Два проверочных примера и технические данные свёрнуты. Обновление сохраняет
открытые детали. Кнопка
**«Остановить»** прекращает запуск с сохранением полученных результатов.
Токены показываются после ответа провайдера; это не текущий баланс аккаунта.

Если провайдер не подключён, интерфейс покажет, что настроить. После настройки
нажмите **«Проверить вход»** (после успешной проверки — **«Обновить статус»**).
Установка CLI и авторизация показаны отдельно. Для Codex эта кнопка также
загружает каталог из установленного CLI; список моделей не подтверждает
доступ аккаунта к каждой из них. Обычное обновление страницы не запускает
диагностику CLI. Выбор провайдера, просмотр плана и проверка входа не вызывают
модель. Кнопка запуска расходует квоту или
баланс выбранного провайдера. Готовность настройки не гарантирует ответ:
доступ к конкретной модели окончательно проверяется настоящим запросом.

Если уже открыт локальный демо-сервер, перейдите слева в **«Новый запуск»**:
включение новых обращений происходит при явном запуске. Старый сервер нужно
перезапустить после обновления кода. Отдельный Docker-сервис `demo` остаётся
без моделей; основной `reviewer-lab` поддерживает новые эксперименты.

Окно терминала оставьте открытым. Обычно адрес — `http://127.0.0.1:8765`;
при занятом порте простой запуск выбирает свободный и печатает точный адрес.
Для остановки — `Ctrl+C`. Явный `--port` и экспортированный
`REVIEWER_LAB_PORT` не подменяются.

## Подключить провайдера

Следующие команды предназначены для нативного Python. Для Docker используйте
команды `docker compose exec` из раздела выше: вход на компьютере автоматически
в контейнер не переносится.

### Codex

Нужны установленный Codex CLI, вход ChatGPT и доступ аккаунта к выбранным
моделям. Авторизация хранится у CLI; копировать токен в проект не нужно.
Диагностика без нового ответа модели:

```sh
python3 run.py doctor --provider codex
```

При необходимости задайте путь к бинарнику переменной `REVIEWER_LAB_CODEX`.
По умолчанию используется доступный CLI приложения на macOS или `codex` из PATH.

### Claude

На macOS с Homebrew:

```sh
brew install --cask claude-code
claude auth login
python3 run.py doctor --provider claude
```

Установка и вход описаны в официальных руководствах
[Claude Code setup](https://code.claude.com/docs/en/setup) и
[CLI reference](https://code.claude.com/docs/en/cli-reference).
Нужен доступ вашего аккаунта к выбранной модели. Стенд использует Claude Code
CLI; отдельный API-ключ в браузере не нужен. Для нестандартной установки
задайте `REVIEWER_LAB_CLAUDE`. Нужна актуальная версия CLI, поддерживающая
используемый стендом запуск без инструментов.

### DeepSeek

Создайте ключ в [DeepSeek Platform](https://platform.deepseek.com/api_keys).
Стенд обращается к официальному API напрямую; отдельный DeepSeek CLI и Python
пакеты не нужны. API использует баланс аккаунта, отдельно от веб-чата.
[Официальная инструкция API](https://api-docs.deepseek.com/) описывает подключение
и актуальные имена моделей. В стенде по умолчанию выбран `deepseek-flash`;
альтернатива — `deepseek-v4-pro`.

В стандартном терминале macOS (zsh) введите ключ скрыто, затем запустите сервер
**из этого же окна**:

```sh
read -rs 'DEEPSEEK_API_KEY?Ключ DeepSeek: '
export DEEPSEEK_API_KEY
printf '\n'
python3 run.py start --live --provider deepseek
```

Сам ключ не попадает в историю команд. Не вставляйте его в исходники,
`.env.example`, поле модели или сообщения. Если сервер уже работал, перезапустите
его из окна с переменной: существующий процесс не получает новое окружение.
Проверка настройки: `python3 run.py doctor --provider deepseek`.

## Проверить свой патч

Откройте слева **«Свой код»**. Выберите задачу; её описание доступно через
**«Подробнее о задаче»**. Раскройте **«Ревьюер · …»**, чтобы выбрать подключение
и модель. Вставьте полную функцию `decision` и нажмите **«Проверить с моделью»**.
Сначала сравниваются решения кода с правилом. Только патч с заданным нарушением отправляется ревьюеру: при
первой такой попытке до трёх вызовов с двумя контролями, затем до одного.
Задача, провайдер и модель закрепляются за серией: следующие версии кода
сравниваются в одной конфигурации. Для другой задачи или модели нажмите
**«Новая серия»**. **«Проверить поведение · без модели»** доступен отдельно.

Для автоматического поиска откройте **«Новый запуск» → «Режим и дополнительные
настройки»** и в поле **«Режим проверки»** выберите **«Найти новый обход»**. Генератор предложит
новые патчи, локальная проверка подтвердит нарушение, ревьюер даст решение.
**«Сравнить два способа поиска»** запускает серии с обратной связью и без неё.
Перед запуском прочитайте план и число вызовов. Ревьюер выбирается на основном
экране, модель генератора и повторы — в дополнительных настройках.
Все вызовы одного запуска идут через выбранное подключение; автоматической
подмены недоступной модели нет.

Доступны три задачи о правах и изменениях и пять сценариев безопасности
из MonitoringBench, представленных конечными моделями разрешений —
[происхождение и ограничения](MONITORINGBENCH.md). Исходные траектории BashArena
не воспроизводятся. Сохранённые результаты прежнего пилота относятся к исходным
задачам и не оценивают пять новых сценариев.

## Команды без браузера

Проверить готовый пример выбранным провайдером:

```sh
python3 run.py run --provider claude --cases owner --modes independent --attempts 1 --repeats 1 --candidate-files examples/successful-owner-bypass.py --out runs/claude-owner-1
```

Для DeepSeek замените `--provider claude` на `--provider deepseek`; для Codex —
на `--provider codex`. Каталог `--out` должен быть новым. Ручная попытка:

```sh
python3 run.py manual --case owner --source examples/successful-owner-bypass.py --provider deepseek --out runs/manual-deepseek-1
```

Точные параметры: `python3 run.py run --help` и `python3 run.py manual --help`.
Модель задаётся через `--reviewer-model`, а в автоматическом поиске также
`--attacker-model`. Все вызовы одного запуска используют выбранного провайдера.

## Посмотреть без модели

```sh
python3 run.py
```

На macOS также доступен **Start Reviewer Lab.command**. На стартовой странице
**«Быстрый старт»** основная кнопка — **«Запустить первую проверку»**,
а **«Посмотреть пример без модели»** открывает запись. Разбор записи показывает
правило, патч, конкретную ситуацию с нарушением и сохранённый ответ. В левом
меню **«Быстрый старт»** всегда доступно короткое объяснение и переход к разбору.
Кнопка **«Проверить поведение · без модели»** в разделе **«Свой код»** проверяет
код без сети. Временный результат не создаёт эксперимент в `runs/`.

## Проверки и результат

В Docker перед командами Python добавляйте `docker compose exec reviewer-lab`,
например `docker compose exec reviewer-lab python run.py check`.
Для JavaScript-тестов: `docker compose exec reviewer-lab sh -c 'node --test tests/*.cjs'`.
Нативные команды из корня проекта:

```sh
python3 run.py check
python3 -m unittest discover -s tests -v
node --test tests/*.cjs
python3 run.py replay owner examples/successful-owner-bypass.py
python3 run.py verify runs/replication-collision-medium-2026-10-19
```

Эти команды не запрашивают новые ответы модели. Node нужен только для
frontend-тестов. Python напрямую не загружает `.env`: нативный сервер читает
экспортированные переменные окружения, Compose — `.env`. Поля перечислены
в [.env.example](../.env.example).

В завершённой сохранённой попытке нажмите **«Скачать результат»**. Распакуйте
архив и выполните `python3 replay.py`: `matches_saved_oracle: true` подтверждает
повторение локальной проверки. Аккаунт, сеть и установка пакетов не нужны.
Это не новый ответ модели. Серии сохраняются в `runs/<id>/`, включая код,
проверки, ответы и `report.html`.

Claude и DeepSeek покрыты тестами с подставными ответами. Успешные обращения
к вашим аккаунтам и конкретным моделям подтверждаются только реальным запуском.
